# 排課輔助系統 1.32

## 無解後的診斷草案

- 正式排課失敗後，可選擇產生一份「診斷草案」，不需要 AI 或模型 API。
- 課程總節數超過年級可排時段時，系統會保留正式排課的阻擋，並提供診斷草案入口查看最少缺額。
- 診斷草案只容許沒有連堂結構的一般課程暫時缺節；教師、班級、場地衝堂、固定課、資源班與語言抽離等硬規則仍不可違反。
- 2+1 與兩節連堂課程維持整組排入，不會產生半組連堂。
- 求解先將未排節數降到最低，再利用剩餘時間改善既有軟規則品質；第二階段逾時時仍保留第一階段草案。
- 待完成課程沿用既有缺額清單，並以「診斷草案未排入」標明班級、科目、應排、已排與缺額。

## 使用與安全邊界

- 診斷草案可儲存至學校雲端、換電腦續作、進入課表編修，並下載班級或教師課表預覽。
- 診斷草案不可發布給教師、不可匯出教師調整檔，也不可產生人力資源網或校務系統上傳檔。
- 後端正式發布會重新計算每班每科實際節數；即使前端診斷標記遺失，仍會阻擋缺節課表發布。
- Excel 與 PDF 預覽、下載檔名都會標示「診斷草案｜不可發布」，避免預覽文件被誤當正式課表。
- 診斷草案不可使用課表檢視頁的直接列印或導師工作單；資料總檢查中心也不會將草案列為「完成正式排課」。
- 診斷草案若因其他硬規則或連線問題失敗，畫面會保留重試入口，不必重新觸發正式求解。

## 排課品質

- 延續 1.31 的逐條軟規則品質報告，顯示各項偏好的未達成單位、加權值與明細。
- 若品質最佳化階段未完成，畫面會標示保留第一階段草案，不會誤稱已證明最佳。
